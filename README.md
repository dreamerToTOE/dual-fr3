# dual-fr3

This repository contains the **FR3-only** four-wall scene package for the
150 mm cube study. It is intentionally separate from the earlier episode
robot project and does not reuse its six-axis robot, runner, or validation
files.

The package describes:

- two Isaac Sim Franka FR3 robots;
- fixed L-shaped side-suction preview tools mounted at `fr3_link8`;
- the expanded four-wall geometry with a 150 mm cube and five target positions;
- two visual Y-axis rails using the current 1.5 m travel range.

Run the static preview inside Isaac Sim 4.5 with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_four_wall_preview.py
```

The script writes `preview/fr3_four_wall_preview.usda` and two PNG captures.
The FR3 USD is resolved from the Isaac Sim asset root at runtime, so the
machine must have the official FR3 asset available.

## Base snapshots

The `base` history keeps two experiment states for the same 150 mm FR3 scene.
Commit `9a5dd79` is the no-cache environment snapshot. It contains the scene,
validation code, preview assets, and reports while the runtime planner creates
the A/B1/B2 paths online. It is the baseline for studying planning-time
behavior and online anomalies.

Commit `d2cf2d4` is the stored-trajectory environment. It adds the complete
120 Hz A/B1/B2 runtime cache, cache-first replay, state checks, and fallback to
the online RRT/IK planner. The current `base` branch points to this version,
while `9a5dd79` remains an ancestor in the same branch history.

`validation/fr3_b2_collision_plan.json` is the collision-constrained B2
preflight plan used by both states. The complete runtime cache generated by an
A/B1/B2 execution is stored separately in
`validation/fr3_trajectory_cache.json`.

## idea one vision branch

Branch `idea-one` records the first innovation study from the research plan.
It adds a rear RGB camera setup, a visual ArUco marker on the Cube top face,
and a report path for combining visual observations with robot state and
kinematic prediction. The preferred camera asset is Isaac Sim's Intel
RealSense D455 at `Isaac/Sensors/Intel/RealSense/rsd455.usd`, using its color
camera calibration and retaining its color/pseudo-depth paths for the next
fusion step.
The camera is placed behind and above the back wall so occlusion remains part
of the experiment. The first probe records missed observations instead of
moving the camera to guarantee global visibility.

The visible scene includes a simplified D455 housing with three lenses and a
table-mounted stand behind the rear wall. These meshes are visualization only
and have no colliders. The housing and lenses stay behind the optical plane
so the sensor does not see its own housing. Mount dimensions are recorded
in `vision.mount`.

The 2026-11-17 visual D455 probe loaded the asset, rendered the back-wall
scene, and detected ArUco ID 23 on the Cube once in a 640x480 frame. Isaac
Sim 4.5 leaves the D455 color prim with unsupported projection metadata and
its direct render is blank, so the capture uses a pinhole camera with the
D455 color intrinsics while retaining the D455 asset and camera path in the
report. The image and result are recorded in
`validation/idea_one_d455_aruco_probe.json`. The automatic runner uses an
independent sensor render product in visible mode and schedules ArUco
sampling as an asyncio task, without calling a render API that advances
PhysX. Full reference-versus-camera statistics are recorded in the
independent comparison experiment below.
The overview viewport stays at 1400x900 while the D455 sensor keeps its own
640x480 render product, so the UI is not enlarged from the sensor frame.
Isaac Sim Cube poses, robot joints, and flange poses remain available to
the existing controller and safety checks. Visual pose estimates are only
logged and compared against ground truth; a fusion estimator has not yet
replaced the controller state inputs.
The earlier camera-mount acceptance passed A/B1/B2 with matching
control/physics steps. Its 1400x900 capture is
`validation/idea_one_camera_full_scene.png`.

Run the visible stand/render check with
`/home/ubuntu2004/isaacsim-4.5.0/python.sh tests/isaac_camera_mount_smoke.py`.
It verifies separate image sizes, marker ID 23, and no stand colliders, and
saves overview/sensor PNGs plus `validation/idea_one_camera_mount_smoke.json`.

## Independent Cube position comparison

The experiment now logs two separate streams in
`validation/idea_one_vision_comparison/`: `ground_truth.jsonl` records the
Isaac Sim Cube position for reference, while `camera.jsonl` contains only
RGB/ArUco position observations (or an explicit missing observation).
`fr3_vision.py` receives an RGB frame, fixed camera intrinsics/extrinsics,
and known marker/Cube dimensions. It never receives a Cube ground-truth
position. The controller still uses its existing simulation state; this
experiment measures perception accuracy before connecting a fusion estimator.

Each camera observation uses its own rendering frame ID and exposure time.
The evaluator matches it to the 120 Hz reference history within half a
physics step. It records readout latency, excludes duplicate image frames,
and leaves missing detections empty instead of substituting ground truth.
Pose recovery uses the full PnP translation/rotation and marker-to-Cube offset.
The camera calibration is fixed before the run; no ground-truth bias fitting
is performed.

Run the automatic task, then generate the comparison plot and statistics:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_ab_visual_runner.py --close-on-finish
python3 fr3_vision_comparison.py validation/idea_one_vision_comparison/comparison.jsonl
```

The directory also contains `metadata.json`, complete paired
`comparison.jsonl`, `comparison.csv`, `summary.json`, and `comparison.png`.
Statistics include XYZ bias/absolute error and 3D mean, median, RMSE, P95,
and maximum error, both overall and by task phase. Error statistics use
only valid time-matched detections; visibility/missing-frame counts remain
separate. The headless comparison is preserved independently in
`validation/idea_one_vision_comparison_headless/`.

The completed visible run had 906 matched detections out of 1,303 sampling
attempts (69.5%). Its 3D mean/RMSE/P95/maximum errors were respectively
24.8/29.9/56.5/134.8 mm. Stage mean errors were A 35.6 mm, B1 34.9 mm,
and B2 16.8 mm; the worst observation was during `B1_contact_transit`.
The mean signed XYZ errors were [+2.7, -12.5, -19.4] mm. All missing and
large-error observations are retained; no ground-truth correction or outlier
removal was applied. In visible mode, image readout lagged exposure by
16.7 ms; every matched reference used the exposure time (zero pairing delta).
Both headless and visible A/B1/B2 proxy-contact runs passed with 10,426
matching control/physics steps and zero uncommanded physics steps.

This is a comparison of simulated RGB sensing with PhysX ground truth.
The pinhole model has zero distortion; physical D455 calibration/noise and
fusion-based control are not validated by this comparison.

The recorded scene parameters are `cube_size_m=0.15`, Cube supply center
`[0.0,-0.3,0.787]`, back-wall target center `[0.0,1.076,0.787]`, B2 left-wall
target `[-0.245,1.076,0.787]`, wall inner bounds `x=±0.320`, right rail contact
`base_y=0.65`, FR3 bases `x=±0.44`, and a 1.5 m Y-axis rail. The machine-readable
snapshot is `validation/fr3_environment_snapshot.json`.

After a complete run, the runner stores the 120 Hz phase trajectories in
`validation/fr3_trajectory_cache.json`. The cache includes raw joint
waypoints, time-sampled joint commands, expected Cube centers, collision-check
reports, and rail base samples. Regenerate it with the automatic runner after
changing the scene configuration.

The runner loads a `COMPLETE` cache for the matching scene before each A/B1/B2
phase. It checks the measured joint start, TCP/Cube pose, and rail endpoints
before replay. A mismatch disables replay for the remaining phases and uses
the existing online RRT/IK planner. PhysX contacts, joint limits, Cube
deviation, and B2 dual-contact checks remain active during replay. A measured
collision or mid-phase deviation stops the run for inspection rather than
silently continuing.

This is a geometry preview only. It does not claim PhysX contact, suction,
ROS, IK, trajectory, or full B2 validation.

## Local A/B validation gates

The current A/B semantics are kept in `fr3_four_wall_scene_config.json`:

- A: dual-arm pickup at the supply position, lift over the front wall, and
  place at the landing position;
- B1: left side-face contact and `+Y` push to the back wall;
- B2: move the right tool to the Cube suction-height plane, align outside the
  right face, approach horizontally along `-X`, then push to the left wall
  while preserving the back-wall contact.

Run the geometry/runtime preflight with:

```bash
python3 fr3_ab_preflight.py
```

Run the Isaac Sim headless dynamic loading smoke test with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_ab_dynamic_smoke.py --no-window
```

The smoke test creates a real `PhysicsScene`, dynamic `/World/Cube`, collision
walls/tools/cups, and both FR3 articulations, then checks that the supply cube
settles under gravity. Its report is written to `validation/`; `ab_status`
remains `BLOCKED` until a dedicated FR3 trajectory and suction/contact
controller is implemented.

Run the Lula waypoint reachability gate with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_ab_ik_preflight.py --no-window
```

The IK preflight checks reachability only. The collision-constrained B2 plan
uses the right rail at `base_y=0.65 m`, an elevated wrist with the side
suction tool, a suction-plane alignment waypoint, and a separate horizontal
approach segment. Rebuild that plan with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_b2_collision_plan.py
```

Start the visible automatic task with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_ab_visual_runner.py
```

Add `--headless` for the same task without a window. The viewer pauses at
completion or at the first failed check and retains the scene for inspection.
The runtime report is `validation/fr3_ab_visual_runner.json`.

The visible runner advances one 120 Hz physics step per control sample and
uses render-only updates for the 60 Hz viewport. Planning progress therefore
does not advance the Cube or the robots. The runtime report records both
control and physics step counts.

Free transfers use RRT-Connect with joint limits and full-arm collision checks.
The final 120 Hz trajectories are checked again after timing and blending.
Checks include official FR3 Lula collision spheres, every custom tool support
and cup, the Cube, walls, floor/table, interarm and nonadjacent self collisions.
Both arms share one 14-joint timeline during coordinated transfers and B2.
All FR3 body and custom tool colliders remain enabled. Only the removed stock
hand/fingers have their geometry hidden and colliders disabled.

PhysX contact events stop execution on unintended robot/tool contact. Only
phase-authorized cup/Cube contact up to 3 mm penetration is allowed. The
planning geometry is conservative spheres/boxes, not a swept-mesh certificate.
A still uses labelled temporary PhysX fixed joints; Surface Gripper validation
is separate. A successful Cube endpoint alone is insufficient to pass the task.
