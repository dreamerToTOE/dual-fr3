# dual-fr3

This repository contains the **FR3-only** four-wall scene package for the
150 mm cube study. It is intentionally separate from the earlier episode
robot project and does not reuse its six-axis robot, runner, or validation
files.

The package describes:

- two Isaac Sim Franka FR3 robots;
- fixed L-shaped side-suction preview tools mounted at `fr3_link8`;
- the expanded four-wall geometry with a 150 mm cube and five target positions;
- two visual Y-axis rails using the current 1.5 m travel range.

Run the static preview inside Isaac Sim 4.5 with:

```bash
/home/ubuntu2004/isaacsim-4.5.0/python.sh fr3_four_wall_preview.py
```

The script writes `preview/fr3_four_wall_preview.usda` and two PNG captures.
The FR3 USD is resolved from the Isaac Sim asset root at runtime, so the
machine must have the official FR3 asset available.

## Base snapshots

The `base` history keeps two experiment states for the same 150 mm FR3 scene.
Commit `9a5dd79` is the no-cache environment snapshot. It contains the scene,
validation code, preview assets, and reports while the runtime planner creates
the A/B1/B2 paths online. It is the baseline for studying planning-time
behavior and online anomalies.

Commit `d2cf2d4` is the stored-trajectory environment. It adds the complete
120 Hz A/B1/B2 runtime cache, cache-first replay, state checks, and fallback to
the online RRT/IK planner. The current `base` branch points to this version,
while `9a5dd79` remains an ancestor in the same branch history.

`validation/fr3_b2_collision_plan.json` is the collision-constrained B2
preflight plan used by both states. The complete runtime cache generated by an
A/B1/B2 execution is stored separately in
`validation/fr3_trajectory_cache.json`.

collision or mid-phase deviation stops the run for inspection rather than
silently continuing.

## Virtual six-axis wrist force feedback (idea-one, 2026-11-17)

Each arm now has an articulated fixed-joint sensor between `fr3_link8` and
the independent `ABSideTool` rigid body. The blue 12 mm sensor housing replaces
the first part of the original tool stem, retaining the TCP and the previous
conservative collision envelope. Every tool collider remains enabled. A's
temporary Cube attachment is connected to the tool body downstream of the
sensor, so the payload does not bypass the measurement.

Each virtual tool assembly has mass 0.3 kg, COM `[0, -0.06, 0.055]` m on the
left and `[0, 0.06, 0.055]` m on the right, and principal inertia
`[0.0015, 0.0007, 0.0012]` kg m². These are declared simulation parameters,
not a hardware calibration. They are stored in `wrist_force_sensors` in the
scene configuration and in each recording's `metadata.json`.

The 120 Hz recording reads actual PhysX incoming joint reactions in
`[Fx,Fy,Fz,Tx,Ty,Tz]` order (N and N m), not commanded gravity compensation
or controller efforts. The raw sign is parent-on-tool; the local frame and
origin coincide with the flange joint anchor. The residual is
`-raw_reaction - tool_gravity_wrench`, expressed both locally and in world
axes, with moments still referenced to the sensor origin. Tool inertia is
not removed. Cube truth and contact-pair identifiers are not sensor inputs;
phase names are evaluation context only. These are ideal physics signals
without added sensor noise, latency or saturation.

The first sensor-origin acceptance used `validation/idea_one_wrist_ft_visible/`
and `validation/idea_one_wrist_ft_headless/`; these historical directories are
preserved. Current commands and the TCP-origin extension are documented below.
Each run writes `runner_report.json`, `metadata.json`, `wrench.jsonl.gz`,
and a separate `trajectory_cache.json`; camera/reference streams are under
`vision/`. The analyzer produces `summary.json`, `wrench.png` and a B-only
`wrench_contact.png`. Saved nominal A/B1/B2 paths are still loaded from
`validation/fr3_trajectory_cache.json`, with the existing deviation/contact
guards. New runs do not overwrite that baseline cache or the earlier
`idea_one_vision_comparison` results. Use a fresh output directory to retain
multiple force-feedback runs.

The 28 actual PhysX load cases cover two sensor orientations, gravity,
all six positive/negative channels, and the moment of an offset force.
All passed, with maximum component errors `5.37e-7 N` and `2.92e-4 N m`;
the complete calibration record is `validation/idea_one_wrist_ft_load_check.json`.
The analyzer separately checks empty-tool residuals, the suspended bilateral
payload force against the configured Cube weight, B1/B2 pushing directions,
and the continuity of B2's left support force. A 1.5 s stationary window is
recorded after lifting and after crossing the front wall for this load check.

The complete visible acceptance is preserved in `validation/idea_one_wrist_ft_visible/`:
10,786 matching control/physics samples, zero uncommanded physics steps, and no
unexpected PhysX contact. Empty-tool residuals passed. Suspended combined

Sensor checks passed, but the force profile has task-level warnings:

- B2 left median Fy was -0.3042 N, but only 58.6% of the evaluated moving

`summary.json` distinguishes sensor checks from these task warnings as
`PASS_FORCE_FEEDBACK_WITH_TASK_WARNINGS`. The release-peak screening rule
is relative to push forces; it is not a robot or sensor safety rating.

classification. In particular, large opposing A loads can come from the two

### A closed-chain force correction

The original A commands were independently interpolated in joint space.
Offline official-URDF FK found up to 2.763 mm and 0.4266 degrees of relative
TCP drift inside a nominally rigid bilateral grasp. The two fixed attachments
opposed those inconsistent commands: the 317.77 N individual forces largely
cancelled, so checking only their sum against Cube weight missed the fault.
`validation/idea_one_a_force_diagnosis/` records the original force and command
evidence without modifying the historical logs.

A now samples one shared Cartesian quintic translation at 120 Hz, retaining
both tool orientations and relative grasp geometry at every sample. Local
IK uses the existing TCP-aware Jacobian. Samples are collision-checked and
executed directly, without another joint spline. The fixed attachment and
sensor models, Cube mass, robot/tool collisions and measured wrench signals
are unchanged.

The first geometry-only pilot still reached 124.11 N. Its joint tracking
lag fitted about 0.095 s: the position-only commands left the PD drive's
velocity target at zero, so damping resisted the motion. A transfer now
also commands the derivative of the same joint samples. Velocity targets
are explicitly zero at endpoints, in holds/other phases, and on exit or
failure. Actual position and velocity targets are recorded separately from
measured joints. No additional six-axis admittance loop or softer attachment
was needed for this correction.

`idea_one_a_force_pilot1` retains the geometry-only failure. In
`idea_one_a_force_pilot2`, A passed, but B2 side-wall seating reached the
10.158 N stop while its measured geometric gap remained 23.568 um: the old
20 um seating condition kept pressing. Seating now accepts 30 um, with the
same minimum contact-force condition and unchanged 10 N force protection.
The saved-pose regression covers that solver residual. Neither failed pilot
is a normal full-flow training example.

The predeclared A envelope covers **all** A samples, including attachment,
release and stationary transitions: each arm must stay within 30 N and
3 N m at the TCP, and the bilateral difference-force diagnostic within
15 N. The live A guard stops on an exceedance after recording the failing
sample. B1 uses the same individual force/moment limits over every B1 sample;
the earlier B2 force/contact/release contract remains required. These are
simulation acceptance criteria, not hardware safety ratings.

### Contact-state skill library and multisource recognition baseline

`fr3_contact_skills.json` contains eight physical contact states plus
`UNKNOWN` and `INCONSISTENT`, and ten skill descriptions tied to existing
runtime callables. Each skill declares entry/target states, controller,
success conditions and abort conditions. They cover alignment, attachment
proxy establishment, bilateral transport, landing/release, front pushing,
rear preload, right-arm plane alignment, lateral pushing, unloading/retreat,
and holding/reobserving. This is a robot skill catalog; the current observer
recommends eligible skills without taking over the validated controller.

| State | Evidence required by the baseline |
| --- | --- |
| `NO_TOOL_CONTACT` | Fresh visual Cube box separated from both encoder TCPs; fusion also requires unloaded wrists |
| `BILATERAL_SUPPORTED` | Opposed side loads and loaded-FK centers at support height |
| `BILATERAL_SUSPENDED` | Both wrists carry vertical payload |
| `LEFT_FLOOR_CONTACT` | Loaded front TCP, support height, outside rear-wall band |
| `LEFT_REAR_CONTACT` | Loaded front TCP and rear-wall constraint geometry |
| `DUAL_REAR_CONTACT` | Front and side loads with rear-wall geometry |
| `DUAL_CORNER_CONTACT` | Front and side loads with both wall constraints |
| `RELEASED_CORNER` | Unloaded wrists and both TCPs separated from the visual Cube in the coarse corner zone |
| `UNKNOWN` / `INCONSISTENT` | Insufficient evidence / conflicting evidence or overload |

`fr3_contact_state.py` accepts only timestamped camera observations, TCP
six-axis wrenches, encoder-FK TCP positions/cup normals and static scene
geometry. Task phase, desired skill, trajectory progress, Cube ground truth,
attachment state and PhysX contact events are excluded from this interface.
Thresholds come from the library's `observation_contract`. Camera observations
are available only after their receive time and expire after 0.25 s; a miss
never becomes a zero-error pose. Three consecutive classifications confirm a
state; loss of evidence and overload are reported immediately.

The observer runs at 120 Hz. Its force-only ablation retains encoder FK and
static geometry but ignores the camera; vision-only retains encoder geometry
but ignores force. Loaded FK predicts a face-aligned Cube center only when
normal force supports the contact hypothesis. Camera consistency is checked
at a coarse 120 mm band because historical B1 visual outliers reached 130 mm.
Wall constraints use loaded FK, not a claim of micrometer visual accuracy.
The rear/side FK band is 0.2 mm. These explicit rules establish an explainable
baseline; they do not establish a learned fusion contribution.

The independent evaluator records current PhysX pair lifecycles and normal
impulses for Cube/cups, support and walls, plus actual attachment joints and
Cube geometry. Positive contact-offset manifolds are distinguished from
geometric touching; old impulses are not reused as current force. Physical
wall contact and 50 um geometric adjacency are logged separately. Reference
state labels use their union to account for wall solver offsets. Missing
physical snapshots become unknown reference labels, not free-space labels.

Each run writes independent compressed sensor-input, reference and prediction
streams under `contact_states/`, plus a state timeline, per-class confusion,
precision/recall/F1, coverage and event-delay results. Unknown predictions
count against accuracy and coverage; decided-only accuracy is shown separately.
Only unknown **reference** samples are excluded, with their predictions reported
separately. Event delays use reference intervals lasting at least 0.25 s and
do not trim samples from the accuracy calculation. Full-camera-outage replay
is a sensor ablation, not a physical disconnection experiment.
