# S5 单面承载漏检诊断

S5 指箱底仍受支撑、吸盘仍在接触，且只有一个水平方向的边界实际传力。用原评分程序复现拟合法的 69/4848（1.4%）。其中第 4 箱有 4791 个 S5 真值步，占 98.8%，通用观察器命中 35 步。第 5 箱直推贴后墙有 57 个 S5 真值步，命中 34 步（59.6%）。诊断沿用原 PhysX 真值、因果相机时间戳及冻结的识别参数。 [对照试次与数据](README.md)

## 通用观察器漏在哪一关

第 4 箱的 4791 个 S5 步都有 0.4 s 内的相机观测。进入受支撑推压分支并检查几何的 4786 步，均找到实际传力的边界作为几何候选。候选使用融合位姿、邻箱观测和投影间隙。在 ArUco 对应试次中，侧邻箱有 2770 步落在候选范围之外。

| 第 4 箱 S5 首个未通过的条件或结果 | 拟合法步数 |
| --- | ---: |
| 朝实际承载边界的推力分量未达到门限 | 2958 |
| 缺少沿该边界法向的连续指令与末端响应 | 989 |
| 有法向响应，接触确认条件未通过 | 771 |
| 未进入受支撑推压判定 | 5 |
| 找到该边界，同时误报第二个边界为 S6 | 33 |
| 正确识别 S5 | 35 |

2958 步与 989 步合计占第 4 箱通用判据漏检的 83.0%。第 4 箱换臂后主要由右臂沿 +Y 推向后墙，右侧邻箱仍沿 X 方向传力。通用判据先检查当前推力是否指向邻箱，再找同一法向上的腕力与指令响应。继承已确认的邻箱承载证据时还要求先确认一面墙，因此在只有侧邻箱承载的时段很难维持 S5。 [通用观察器](../../seven_observer.py)

横推期间的 722 个 S5 步中有 711 步侧向力至少为 1 N。通用判据漏掉的 687 步均显示编码器推进超过 0.5 s 窗口内指令推进量的 35%，其中一些步同时未达到 0.30 N 的增力条件。这个判据用于从推进受阻确认新接触，已经贴靠但末端仍跟随指令时容易漏检。第 4 箱有 3480 个 S5 步的实际水平承载低于 1 N，这些步通用判据均未识别。 [法向响应判据](../../seven_observer.py#L170)

## 第 4 箱专用观察器

| 时段 | ArUco 识别率 | 视觉拟合法识别率 |
| --- | ---: | ---: |
| 横推 | 27/369（7.3%） | 35/722（4.8%） |
| 换臂 | 0/34（0.0%） | 5/1022（0.5%） |
| 后推至开始撤离 | 1666/3001（55.5%） | 1572/3047（51.6%） |
| 合计 | 1693/3404（49.7%） | 1612/4791（33.6%） |

专用判据能用右腕的横向力或绕 Z 力矩判断侧向承载。拟合法漏检的侧载步中，换臂有 938 步、后推有 1047 步仍在侧向间隙允许范围内，右腕缺少符合条件的侧向力或力矩信号。两阶段合计 1985 步。

两次从同一实测断点分别运行，换臂动作及接触持续时间有差异。如果按 ArUco 三个时段的 S5 真值步数对拟合法的分段识别率重新加权，拟合法为 46.0%。实际汇总为 33.6%，长换臂段里的持续侧载占比增加，是两次汇总差距的主要来源。 [第 4 箱专用观察器](../../u4_contact_observer.py)

## 复算

从仓库根目录运行。诊断脚本复用原观察器，并记录几何候选、指令响应和承载力分布。响应条件可同时失败，JSON 中的响应失败计数允许重叠。 [逐段诊断数据](s5_diagnosis.json)

```bash
e=scenes/w760_300mm_two_layer/experiments
d="$e/results/fitting_vs_aruco_20261126"
python3 "$e/s5_diagnosis.py" "$d/manifest.json" /tmp/fr3-s5-diagnosis.json
```
